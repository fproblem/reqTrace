# Тестирование выделения текста (highlight) — полигон и разбор бага

Ветка: `fix/highlight-selection`.

Документ для QA: как воспроизвести баг «подсветка улетает в начало страницы» и
где именно ломается выделение. Сопровождает тестовую страницу-полигон, которую
можно создать в один клик.

## Как открыть полигон

В левой панели «Страницы» нажмите **+** → внизу формы кнопка
**«🧪 Тестовая страница форматирования»**. (Если страниц ещё нет — кнопка
**«🧪 Тест форматирования»** показывается на пустом экране.)

Создаётся локальная страница (без обращения к Confluence) со снимком и baseline.
Она написана как **итоговый HTML**, поэтому разбиение на блоки на бэкенде
(`extract_blocks`) и на фронтенде (`getContentBlocks`) совпадает — под тестом
остаётся ровно одна переменная: логика вычисления якоря выделения, а не
различия raw/processed-разметки.

Реализация: `POST /api/pages/demo/formatting` →
`reqtrace/backend/app/routers/pages.py` (`FORMATTING_TEST_HTML`,
`add_formatting_test_page`).

## Суть бага

Симптом: на некоторых фрагментах (особенно в списках) после выделения и нажатия
«Привязать тесты» подсветка появляется не там, где выделяли, а **на первом слове
страницы** (заголовок «🧪 Полигон форматирования…»).

Причина — фолбэк в `handleMouseUp`,
[`reqtrace/frontend/src/pages/PageDetailPage.tsx:268`](reqtrace/frontend/src/pages/PageDetailPage.tsx#L268):

```js
if (anchorBlockStart === -1) {
  anchorBlockStart = 0;
  anchorBlockEnd = 0;
  startCharOffset = 0;
  endCharOffset = text.length;   // -> подсветка на блок 0, символы 0..N
}
```

Якорь выделения вычисляется так: среди «листовых» блоков
(`getContentBlocks` → `p, h1–h6, li, td, th, pre, dt, dd`, **не содержащих
вложенных блоков**) ищется тот, который `.contains(range.startContainer)`.
Если такого нет — `anchorBlockStart` остаётся `-1`, и срабатывает фолбэк,
который кладёт подсветку на блок 0.

`range.startContainer` оказывается вне любого листового блока, когда выделяемый
текст лежит:

1. в `<li>`, у которого есть **вложенный список** (такой `<li>` не листовой,
   т.к. содержит вложенный `<li>`);
2. в `<td>` с вложенным списком/абзацем (по той же причине);
3. прямо в `<blockquote>` без обёртки `<p>` (у текста вообще нет блока-предка
   из списка `BLOCK_TAGS`);
4. на границе выделения, попавшей на сам контейнер `<ul>`/`<ol>` или на
   пробельный текстовый узел между пунктами (частое поведение браузера при
   протягивании выделения по списку).

### Вторичный баг: подсветка молча исчезает

Если **начало** выделения попало в листовой блок, а **конец** — в «осиротевший»
текст (например, выделение из обычного абзаца внутрь родительского пункта
вложенного списка), то `anchorBlockStart` валиден, но `anchorBlockEnd`
остаётся `-1`. Фолбэк не срабатывает (он смотрит только на `start`), и
`-1` уходит на бэкенд. При отрисовке в
[`HighlightLayer.tsx`](reqtrace/frontend/src/components/PageView/HighlightLayer.tsx#L70)
`endBlockIdx = anchor_block_end ?? startBlockIdx` даёт `-1` (т.к. `-1 != null`),
цикл `for (bi = start; bi <= -1; …)` не выполняется — **подсветка не рисуется**.

## Карта полигона: что проверять в каждом разделе

Разделы помечены `§N`. Колонка «Ожидание» — что должно происходить;
«Риск» — что, предположительно, сломано сейчас.

| §   | Что выделять | Ожидание | Риск (текущее поведение) |
|-----|--------------|----------|--------------------------|
| §1  | Обычный абзац | OK | эталон |
| §2  | Фрагмент через границы `bold/italic/code/ссылка` | OK, точные смещения | возможен сдвиг смещений на 1 символ из-за trim-логики |
| §3  | Заголовки h3/h4 целиком | OK | — |
| §4  | (а) внутри пункта; (б) **через несколько пунктов** | OK | (б) часто улетает в начало |
| §5  | Нумерованный список | OK | как §4 |
| **§6 ⚠** | **Текст родительского пункта** («Родительский пункт с собственным текстом…») | OK | **улетает в начало** (текст в нелистовом `<li>`) |
| §7  | Пункты с инлайн-форматированием | OK | сдвиг смещений |
| §8  | `<li><p>…</p></li>` | OK (текст в листовом `<p>`) | работает, но блок — это `<p>`, не `<li>` |
| §9  | Ячейки таблицы | OK | как §4 при выделении нескольких ячеек |
| **§10 ⚠** | **«прямой текст ячейки» до списка** | OK | **улетает в начало** (текст в нелистовом `<td>`) |
| §11 | dt/dd | OK | — |
| §12 | Строки внутри `<pre>` | OK | проверить переводы строк |
| **§13 ⚠** | **Вторая цитата** (прямой текст в `<blockquote>` без `<p>`) | OK | **улетает в начало** (нет блока-предка) |
| §14 | Фрагмент через бейдж/ссылку-задачу/эмодзи | OK | сдвиг смещений около инлайн-элементов |
| §15 | Абзац с `<br>` и пробелами | OK | проверить trim ведущих/хвостовых пробелов |

### Подтверждено анализом разбиения на блоки

«Осиротевший» видимый текст (выделение здесь → прыжок на блок 0) на полигоне:

- §6: «Родительский пункт с собственным текстом…» — в нелистовом `<li>`
- §6: «Ещё один родительский пункт…» — в нелистовом `<li>`
- §6: «Уровень 2 — пункт с подпунктами:» — в нелистовом `<li>`
- §10: «Перед списком идёт прямой текст ячейки…» — в нелистовом `<td>`
- §13: «Цитата с прямым текстом без абзаца внутри…» — без блока-предка

## Чек-лист воспроизведения (для отчёта о баге)

1. Создать полигон (см. выше).
2. В §6 выделить текст **родительского** пункта → «Привязать тесты».
   Ожидаемый дефект: подсветка появляется на заголовке «🧪 Полигон…».
3. Повторить для §10 (текст ячейки до списка) и §13 (вторая цитата).
4. Контроль: то же действие в §1/§4(а) — подсветка остаётся на месте.
5. Вторичный баг: выделить от конца §5 (нумерованный список) внутрь
   родительского пункта §6 → подсветка может не отрисоваться вовсе.

## Предлагаемое направление фикса (следующий шаг)

Чинить нужно вычисление якоря в `handleMouseUp` и фолбэк:

- При `anchorBlockStart === -1` **не** кидать подсветку на блок 0. Вместо этого
  найти ближайший листовой блок к `range.startContainer` (подняться вверх до
  ближайшего листового блока-предка; если предок — нелистовой блок с вложенными
  блоками, взять первый вложенный листовой блок, пересекающийся с выделением)
  и пересчитать смещения; либо отдать якорь как «legacy» (без `anchor_block_*`),
  чтобы сработал текстовый поиск `applyLegacyTextSearch`.
- Симметрично обработать `anchorBlockEnd === -1` (не отдавать `-1` на бэкенд).
- Нормализовать границы, попавшие на контейнерные/пробельные узлы
  (`<ul>`/`<ol>`/whitespace), сведя их к листовому блоку.

Фикс намеренно **не** включён в эту правку: полигон отдаётся на «сломанном» коде,
чтобы QA сначала воспроизвёл дефекты и подтвердил карту, а затем фикс проверялся
на тех же §6/§10/§13.
