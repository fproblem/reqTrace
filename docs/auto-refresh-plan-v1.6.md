## 1. Суть

Сейчас статусы привязок актуализируются только когда кто-то нажал «Обновить».
Добавляем ночной прогон refresh по всем страницам всех проектов + перепроверку
кред участников, журналируем итоги и утром показываем каждому участнику дайджест
его проектов: «за ночь 4 привязки перешли в „Требует проверки“, 1 утрачена».

**Главный инвариант: правила статусов привязок не меняются ни на йоту.**
Автопрогон — это тот же `page_service.refresh_from_confluence`, что и кнопка
«Обновить», просто по расписанию. «Утрачено» терминально, статус повышает только
человек, `anchoring-plan-v1.5.9.md` не трогаем. Снимок создаётся только при
реальном изменении текста (ранний выход `has_text_changed`) — прогон не раздувает БД.

## 2. Фундамент (уже в кодовой базе)

- `services/page_service.refresh_from_confluence(db, page, project, cred) -> bool`
  — весь конвейер переноса привязок; статусы решает `anchoring.project()`.
- `routers/pages.sync_tree` — образец обхода «проекты × ok-креды»: на
  `ConfluenceAuthError` метит креды invalid и продолжает по остальным.
- `ProjectCredential.status/last_check_at/last_check_result` (ok|invalid|unreachable),
  `confluence.check_connection`, `POST /projects/{id}/credentials/check` —
  ночная перепроверка кред = существующий код по расписанию.
- Колокольчик-заглушка в шапке (`Layout.tsx`, v1.6.1) — место под дайджест.
- Экран «Тесты»: `GET /projects/stats` (сводка статусов), фильтры `?f=` и точка
  интереса `?key=` — готовые приёмники диплинков из дайджеста.
- Бэкенд — один процесс uvicorn (Dockerfile без `--workers`) → планировщик
  живёт в самом приложении.

## 3. Архитектура

### 3.1 Планировщик (v1.6.2)

- Фоновая asyncio-задача в lifespan FastAPI (`main.py`); никаких новых
  зависимостей/контейнеров. Тик раз в минуту.
- «Пора?» решает не таймер в памяти, а **журнал**: за «сегодня» (по
  `AUTO_REFRESH_TZ`) нет завершённого или идущего auto-прогона И текущее время
  ≥ `AUTO_REFRESH_AT` → запуск. Отсюда бесплатно: рестарт контейнера не теряет
  и не дублирует прогон; сервер, лежавший в 03:00, догонит прогон при старте.
- Advisory-lock Postgres на время прогона — защита от двойного запуска
  (dev `--reload`; гипотетический второй инстанс).
- Конфиг (`config.py` / `.env`): `AUTO_REFRESH_ENABLED=true`,
  `AUTO_REFRESH_AT=03:00`, `AUTO_REFRESH_TZ=Europe/Moscow`. Явная таймзона
  обязательна — контейнер живёт в UTC.
- Ручной запуск для отладки: `docker compose run backend python -m app.jobs.nightly`
  (журналируется с trigger='cli').

### 3.2 Ночной прогон проекта (v1.6.2)

По каждому обычному проекту (демо — мимо), последовательно, пауза ~300 мс между
запросами к Confluence. Порядок:

1. **Перепроверка кред всех участников со статусом ok** (`check_connection`) —
   обновляет `last_check_at`/`last_check_result`; профиль показывает живую дату
   проверки, а не «когда я сам в последний раз нажал». Отклонение → `invalid`
   (+ запись в `cred_issues` журнала → личное уведомление в v1.6.3).
   **Invalid-креды ночью НЕ перепроверяются**: пароль сменился — ночные ретраи
   basic-auth рискуют блокировкой учётки в LDAP; чинит только человек, как сейчас.
2. **Выбор рабочего подключения** — участник с самым свежим успешным чеком.
   401/403 посреди прогона → `mark_invalid`, переключение на следующего
   участника, страница повторяется. Участники кончились → прогон проекта
   останавливается со статусом `skipped: нет рабочих подключений`.
3. **Sync-tree** (решение пользователя — сразу в v1.6.2): та же сверка спейсов,
   что у `POST /pages/sync-tree` — re-parent/переименования, новые виртуальные
   страницы, чистка пропавших виртуальных. Ядро сверки выносится из
   `routers/pages.py` в сервис и переиспользуется эндпоинтом и джобой
   (поведение эндпоинта не меняется). Счётчики — в журнал: с v1.6.2 копятся
   данные для сигнала дайджеста «в спейсе появились новые страницы» (v1.6.3+).
4. **Refresh всех невиртуальных страниц** через `refresh_from_confluence` как
   есть. Переходы статусов джоба снимает сама: статусы привязок до вызова →
   после → diff (конвейер не расширяем). Затронутые тест-ключи фиксируются в
   журнале в момент прогона.
- Сессия БД — **на страницу**: ошибка одной (404 — страницу удалили в Confluence,
  таймаут и т.п.) пишется в журнал (`pages_failed`, причина в details) и не
  валит прогон. `mark_invalid` коммитит сам — совместимо.
- Confluence целиком недоступен (VPN/сеть) → `unreachable`: прогон проекта
  переносится на следующую ночь, доступ и статусы никому не ломаются.
- Оптимизация больших проектов (деталь реализации, можно отложить): перед полным
  fetch — лёгкий `GET ?expand=version,ancestors` без тела; версия равна версии
  последнего снимка → тело не тянем (title/родителя всё равно обновляем).

### 3.3 Модель данных

Миграция v1.6.2 — таблица **`refresh_runs`** (журнал прогонов):

- `id`, `project_id` (FK, index), `trigger` ('auto' | 'cli'),
  `status` ('ok' | 'partial' | 'skipped' | 'failed'),
  `started_at`, `finished_at`;
- счётчики: `pages_total/pages_changed/pages_failed`, `to_outdated`, `to_lost`,
  `tree_added/tree_moved/tree_removed/tree_missing_tracked`;
- `details` JSONB — по страницам: `{page_id, title, changed, to_outdated: [hl_id],
  to_lost: [hl_id], affected_tests: [keys], error}` + `skipped_reason`;
- `cred_issues` JSONB — `[{user_id, username, result}]`.

Отдельная таблица пер-страничных строк не нужна: объёмы ничтожны, дайджест
ведёт диплинками в существующие экраны, а не дублирует их списки.

Миграция v1.6.3 — **`users.notifications_seen_at`** (одна отметка «колокольчик
открыт»; персональных строк-рассылок нет).

### 3.4 Уведомления и дайджест (v1.6.3)

Принцип: **уведомление — представление журнала, а не рассылка.**

- `GET /api/notifications` → `{unseen_count, entries}`: прогоны проектов, где у
  текущего пользователя членство ok (+ его демо — там прогонов не будет, но
  выборка та же, что у `/projects/stats`), за последние ~14 дней; плюс личные
  записи из `cred_issues`, отфильтрованные по `user_id == me`. Требование
  «уведомления только участникам» выполняется по построению — fan-out
  отсутствует, «отправить лишнему» невозможно.
- `POST /api/notifications/seen` → ставит `notifications_seen_at = now()`.
- Бейдж колокольчика = число записей новее отметки, **значимых**: есть переходы
  статусов, утраты, ошибки страниц или проблемы кред. Тихий прогон бейдж не
  зажигает никогда.
- **«Изменений нет» — состояние-подтверждение** (v1.6.5, идея пользователя):
  тихие прогоны попадают в панель одной живой строкой на проект — «изменений
  нет, страницы проверены тогда-то»; хвостовая серия тихих дней схлопывается
  (attempts, first_attempt_at — размах тишины), находки или неудача разрывают
  серию (о них говорят их собственные записи). Строка никогда не непрочитана —
  это уверенность по запросу («в понедельник видно, что ReqTrace следил все
  выходные»), а не новость. Страницы менялись без задетых привязок — текст
  честно говорит об этом.
- **«Не выполнено» — состояние, а не событие** (v1.6.4, следствие почасового
  добора): хвостовая серия неудачных прогонов проекта схлопывается НА ЧТЕНИИ в
  одну живую строку (attempts, first_attempt_at, последняя попытка); первый
  успешный прогон разрывает серию — строка исчезает вовсе. Непрочитанность
  состояния — раз в локальный день (первая попытка сегодняшнего дня), а не
  каждый добор. Журнал при этом остаётся полным — агрегация только в
  представлении (/api/notifications).
- Роутер подключается в `main.py` строго с `dependencies=[Depends(get_current_user)]`
  (иначе упадёт тест-обход маршрутов в `test_auth.py`).
- Дайджест «за ночь» на деле значит «с прошлого взгляда системы»: если днём
  кто-то обновил страницу вручную и разобрался, ночной прогон не найдёт разницы
  и не будет шуметь — двойного счёта нет по построению.

Виды записей и тон текстов (финальные формулировки — на этапе UI):

> **Ночное обновление · Платёжный шлюз** · сегодня, 03:12
> Изменились 3 страницы из 14. Привязки: 4 → «Требует проверки», 1 → «Утрачено».
> Затронуты тесты PAY-101, PAY-104 и ещё 2.
> Клик → `/tests/:projectId?f=…` (фильтры v1.6.1); строки страниц —
> диплинком `?highlight=` к выделению.

> **Ваше подключение к «Платёжный шлюз» отклонено Confluence** · 03:05
> Ночное обновление прошло кредами других участников. Обновите пароль в профиле.
> (личная запись — видна только владельцу кред; клик → `/settings`)

> **Обновление «Wiki Surf» не выполнено** · 03:20
> Нет работающих подключений / Confluence был недоступен. Проверьте креды в профиле.

Цвета — строго фирменные (ICON_TINTS): бейдж янтарный при «требует проверки»,
красный при утратах/ошибках; никакого синего/фиолетового.

## 4. Что сознательно НЕ делаем

- Не меняем правила статусов, конвейер refresh и `anchoring.py`.
- Не перепроверяем invalid-креды автоматически (LDAP-lockout).
- Не строим персональные рассылки/fan-out и каналы доставки (email, мессенджеры)
  — вернуться после прод-развёртывания в корпсети.
- Не добавляем зависимостей (APScheduler) и контейнеров.
- Демо-проекты и виртуальные страницы в прогон не входят.

## 5. Нарезка и порядок работ

**v1.6.2 «Ночное автообновление»** (текущая ветка; ценность: статусы утром уже
актуальны, «Тесты» показывают свежую картину):
1. `config.py`: AUTO_REFRESH_*; миграция 011 `refresh_runs`.
2. Вынос ядра sync-tree из `routers/pages.py` в сервис (эндпоинт не меняется).
3. `app/jobs/nightly.py`: прогон одного проекта (креды → sync → refresh,
   снятие переходов, журнал) + обход всех проектов; запуск как модуль (trigger='cli').
4. Планировщик в lifespan `main.py`: due-логика по журналу + advisory-lock.
5. `/projects/stats` + карточки «Тестов» и профиль: свежесть.
6. Тесты (см. §6), записи changelog по ходу (хук).

**v1.6.3 «Утренний дайджест»**: миграция `notifications_seen_at`, роутер
notifications (protected!), живой колокольчик с панелью, диплинки, личные
кред-уведомления, `api/client.ts` + типы.

**v1.6.4 «Обновление по кнопке и самолечение» (реализовано)** — ответ на
VPN-риск (машина с бэкендом ночью без VPN → unreachable «сжигал» день):
1. Самолечебный добор: раз в час планировщик добирает проекты, у которых за
   сегодняшний локальный день были попытки, но ни одной успешной
   (ok/partial); последняя попытка моложе часа — ждём (возможно, идёт).
   trigger='retry', ночное расписание не задевает.
   Fail-fast при обрыве посреди прогона: после неудачи страницы — контрольный
   check_connection; сеть умерла → прогон прерывается как skipped/unreachable
   (добор дотянет), НЕ перебирая оставшиеся страницы по таймаутам. Найденные
   до обрыва переходы уже применены к привязкам и добор их «не увидит» —
   поэтому прерванная строка журнала отдаёт в колокольчик И дайджест,
   И «не выполнено» (notifications: skipped без раннего return).
2. Кнопка «Обновить страницы сейчас» в меню карточки проекта (профиль):
   POST /projects/{id}/refresh-run → фоновый run_project под общим
   advisory-lock (409 «уже идёт»), креды инициатора в приоритете
   (prefer_user_id); колокольчик после запуска опрашивает чаще
   (событие reqtrace:refresh-run, 20 с × 20 мин).
3. Живой индикатор прогона (по ревью пользователя: «итог придёт в
   колокольчик» слеп для тихих и неудачных прогонов): GET
   /api/notifications/refresh-status — running (строки журнала без
   finished_at моложе 3 ч по моим ok-проектам) + last_finished; статус —
   ЧАСТЬ кнопки колокольчика (по ревью пользователя: принадлежность к
   дайджесту, а не отдельная кнопка): капсула раскрывается влево (лоадер
   RefreshIcon + имя проекта; анимация — grid-колонка 0fr↔1fr как у
   TreeReveal, 0.5s ease-in-out, opacity с фазовым сдвигом, содержимое
   запоминается на время сворачивания, prefers-reduced-motion уважается —
   индикатор видят все участники, движение нарочно спокойное), по
   завершении ~6 с показывает итог даже тихого/неудачного прогона
   (runResultText: «изменений нет» / «Не удалось: Confluence недоступен» /
   «Готово: 2 на проверку») и складывается в прежний квадрат 34px;
   опрос 30 с в покое, 5 с во время прогона; клик — открыть панель.
   Тост «прогон запущен» упразднён — загораживал индикатор.

  демо, чужое — нет), unseen_count, отметка seen; защиту роутера ловит обход в
  `test_auth.py` автоматически.
- Фронт: `npx tsc --noEmit`; вёрстка свежести/панели — ручная проверка.

## 7. Риски и нюансы

- **TZ**: контейнер в UTC — «03:00» без `AUTO_REFRESH_TZ` стало бы 06:00 МСК;
  due-логика тестируется с явной зоной.
- **Аудит Confluence**: ночные чтения идут под учёткой участника — раскрыто
  подписью в профиле; если у команды возникнут возражения, будущая опция —
  сервисная учётка проекта.
- **Нагрузка на Confluence**: последовательный обход, пауза между запросами,
  version-precheck; ночью фон нулевой.
- **Гонка с ручным refresh той же страницы**: существует и сегодня (два
  человека жмут «Обновить»); ночью окно ничтожно. Усиление при желании —
  advisory-lock на page_id в обоих путях.
- **Рост БД**: снимки создаются только при реальных изменениях; журнал —
  строка на проект в сутки; ретеншн — v1.6.4.
- **Однопроцессность**: если когда-нибудь появятся воркеры/реплики,
  advisory-lock уже защищает от двойного прогона.
