# Демо ReqTrace — план выступления

Рабочий документ подготовки (создан 20.07.2026, ReqTrace v1.7.1).
Структура: две части — «презентация» (рассказ) и «демонстрация» (живой показ).
Дополняется по ходу подготовки.

---

## 0. Полный перечень фич (опора для обеих частей)

### Доступ и проекты
- Вход через Google, только домен @surf.dev; сессия 7 дней.
- Мультипроектность: проект = один Confluence + команда; Jira URL — свойство
  проекта.
- Личные креды Confluence у каждого участника (шифруются, не видны даже
  коллегам); членство в проекте = сохранённые креды; живая проверка при
  сохранении; статусы подключения (работает / отклонено / Confluence был
  недоступен — «проверьте VPN») и замок в дереве.
- Личный Jira-токен (PAT) — опциональный, только для чтения названий тестов.
- Демо-проект с демо-страницей — попробовать без Confluence.

### Страницы требований
- Добавление по ссылке: раздел подтягивается целиком, с вложенными страницами.
- Дерево страниц как в Confluence: структура синхронизируется автоматически
  (перемещения, новые страницы); виртуальные страницы-скелет иерархии,
  подключаемые по клику.
- Снимки страницы при каждом изменении; baseline («закреплённая» версия);
  режим «Изменения» — дифф текущей версии с baseline.
- Индикаторы дерева: точки статусов привязок (по худшему), пометка изменений.
- Картинки: место резервируется до загрузки (страница не «едет»), битая
  картинка — аккуратная заглушка её размера.

### Привязки (ядро ReqTrace)
- Выделил текст требования → «Привязать тесты» → ключ из Jira. Привязка —
  маркер, закреплённый за конкретным местом страницы (модель inline-
  комментариев Confluence).
- При каждом обновлении страницы маркер переносится на новый текст диффом
  на сервере — привязка «переезжает» вместе с требованием, ничего не ищется
  заново и не «прыгает».
- Статусы: **Актуально** (подтверждено человеком) → **Требует проверки**
  (текст под маркером изменился; в панели — пословный дифф цитаты: что
  удалено, что добавлено) → **Актуализировать** (человек подтверждает новую
  редакцию). **Утрачено** — текст исчез; статус терминальный (честность:
  решает человек, тесты сохранены для перепривязки).
- Процент покрытия страницы; навигация по привязкам (чипы статусов, стрелки
  ↑/↓, циклический обход); постоянная ссылка на привязку — вставляется в
  Jira/Slack, открывает страницу точно на выделении.
- Панель привязки: карточка статуса с подсказками, цитата с диффом, тесты
  карточками (чип ключа в цвете статуса — кнопка в Jira), безопасное
  удаление, «церемония» актуализации (лоадер → галочка → мягкое схлопывание).

### Тесты и Jira
- Названия тестов из Jira: рядом с ключом видно, какой тест привязан
  (панель + экран «Тесты»); ReqTrace ходит в Jira ТОЛЬКО за названиями —
  ничего не создаёт и не меняет (контракт).
- Валидация при привязке: опечатка/несуществующая задача видна сразу;
  «мёртвые» ключи — серые, некликабельные, значок-информер объясняет причину.
- Названия актуализируются ночным прогоном (тест переименовали — утром имя
  свежее); мягкая валидация формата ключа (TEST-123).
- Экран «Тесты»: ярус 1 — карточки проектов со сводкой покрытия и свежестью;
  ярус 2 — реверс-индекс «тест → какие требования держит и в каком статусе»,
  поиск по ключу и названию, фильтры (с утраченными / требующими проверки /
  нестандартные ключи), пометка «все утрачены», переходы к привязкам.

### Автообновление и дайджест
- Ночной прогон (03:00): перепроверка подключений → синхронизация деревьев →
  обновление всех страниц → перенос привязок → журнал. Осторожность с
  кредами (LDAP не блокируется).
- Самолечение: если ночью не было связи (VPN) — почасовой добор, как только
  связь появится. Обрыв посреди прогона — честный стоп без перебора таймаутов.
- Ручной прогон «Обновить страницы сейчас» с карточки проекта.
- Колокольчик: утренний дайджест (что изменилось, какие привязки перешли,
  какие тесты затронуты — с переходами), личное «ваши креды отклонены»,
  состояние «не выполняется» (серия неудач — одна строка), строка тишины
  («изменений нет — страницы проверены сегодня в 03:02» — уверенность, что
  слежение живо), живой индикатор идущего прогона прямо в кнопке.
- Уведомления строго по членству — «отправить лишнему» невозможно.
- Свежесть на карточках: «Страницы проверены сегодня в …», предупреждение
  при неудачных попытках.

### Помощь и качество жизни
- Инструкция «Как работает ReqTrace» (5 шагов, автопоказ новичку один раз).
- История изменений (человеческий changelog) по клику на версию.
- Подтверждение выхода; фирменная «мягкость»: плавные модалки/меню/поповеры,
  каскад дерева, мягкие переходы экранов, скелетоны и лоадеры без мельканий.
- Инфраструктура: docker-compose, обновление одной командой (update.sh,
  с автобэкапом БД), миграции применяются сами.

## 1. Часть первая — презентация

### 1.1. История: почему появился ReqTrace
> ЗАГЛУШКА — сюда ляжет твой текст (он станет основой). Каркас, в который
> его удобно встроить:
- Боль: требования живут в Confluence и меняются; тесты — в Jira/XRay;
  связь между ними — в головах и умирающих таблицах RTM.
- Момент осознания: правка требования никого не будит — тесты молча
  устаревают, узнаём на проде/регрессе.
- Решение: инструмент, который держит связь «фрагмент требования ↔ тест»
  живой и сам замечает изменения.

### 1.2. Что такое ReqTrace (одно предложение)
Инструмент трассировки покрытия: привязывает тесты к живому тексту
требований в Confluence и сам следит, чтобы покрытие не устаревало.

### 1.3. Как это выглядит в повседневной работе (сценарий «день QA»)
1. Ночью ReqTrace сам перечитал все страницы проектов.
2. Утром — дайджест в колокольчике: «Изменились 2 страницы, 3 привязки
   требуют проверки, затронуты тесты SI-…». Или строка тишины: «изменений
   нет — проверено в 03:02» (после выходных это тоже ответ).
3. Клик из дайджеста → экран «Тесты» → конкретная привязка на странице:
   пословный дифф показывает, что именно поменялось в требовании.
4. Решение человека: актуализировать привязку (тесты всё ещё покрывают) или
   сначала обновить тест-кейсы в Jira. Утраченное — перепривязать.
5. В любой момент: экран «Тесты» отвечает на вопрос «что держит этот тест
   и в каком оно состоянии», ссылка на привязку — прямо в тикете Jira.

### 1.4. Ключевые принципы (чем отличается от «таблицы RTM»)
- Привязка к живому фрагменту текста, а не к странице целиком — и она
  переезжает вместе с текстом при правках (модель inline-комментариев).
- Статусы меняют только автопрогон и человек; никакой магии — «Утрачено»
  терминально, решение всегда за QA.
- Личные креды: ReqTrace видит ровно то, что видит сам участник; Jira —
  только чтение.
- Инструмент замечает изменения сам — не нужно помнить о проверках.

### 1.5. Плюсы (для слайда)
- Живая связь требований и тестов вместо мёртвых таблиц.
- Изменения находят тебя сами (дайджест), а не наоборот.
- Точность до фрагмента текста + честные статусы с диффом «что поменялось».
- Обратный взгляд: по тесту видно все его требования и их состояние.
- Порог входа: страница добавляется ссылкой, тест — ключом; инструкция
  встроена.
- Безопасность: личные креды, шифрование, домен-ограничение, Jira read-only.

### 1.6. Минусы и ограничения (честно; вопросы всё равно зададут)
- Привязка ручная: ReqTrace не «найдёт тесты сам» — он хранит и оберегает
  связь, которую создал человек (осознанный дизайн, а не недоработка).
- Требует стека Confluence + Jira (Server/DC) и сетевого доступа (VPN);
  вход — только корпоративный Google-домен.
- Покрытие = «на требование есть привязанный тест», а не «тест хорош»;
  качество тестов инструмент не оценивает.
- Дифф не всезнающ: экзотические правки (перестановка похожих соседних
  абзацев) могут дать «Требует проверки» там, где хватило бы взгляда, —
  инструмент сознательно перестраховывается в сторону проверки человеком.
- Прод-развёртывание пока локальное (офисный Mac); доступ коллег по сети —
  следующий этап (поддомен + https).
- Один Confluence на проект; XRay-специфики (статусы прогонов) нет — только
  названия (осознанная граница).

### 1.7. Что дальше (roadmap-слайд, из бэклога)
- Очередь проверки: «пройти все требующие проверки» одним потоком.
- Глобальный поиск (Cmd+K).
- Отчёт о покрытии + экспорт CSV.
- Прод-развёртывание для команды.

## 2. Часть вторая — живая демонстрация

### 2.1. Подготовка стенда (чек-лист перед показом)
- [ ] Полигонная страница Confluence с заготовленной правкой (второе окно —
      Confluence, чтобы показать «источник» изменений).
- [ ] Проект с рабочими кредами и Jira-токеном; 1–2 «сюжетные» привязки:
      одна станет «Требует проверки», одна «Утрачено».
- [ ] Свежий прогон до демо (чтобы дайджест был реалистичным) ИЛИ намеренно
      непроверенные изменения — по сценарию.
- [ ] Чистая учётка/окно для показа онбординга (аккаунт без проектов).
- [ ] Запасной план: скринкаст ключевого флоу на случай сети/VPN.

### 2.2. Сценарий показа (≈10–12 минут)
1. **Вход и первый взгляд** (1 мин): Google-вход, дерево проектов,
   инструкция-онбординг (мельком — «инструмент сам объясняет себя»).
2. **Привязка** (3 мин): открыть страницу → выделить требование →
   «Привязать тесты» → вставить ключ из Jira → название подтянулось сразу,
   опечатка была бы поймана; показать процент покрытия и ссылку на привязку.
3. **Изменение требования** (3 мин): в соседнем окне поправить текст в
   Confluence → «Обновить страницы сейчас» с карточки проекта → живой
   индикатор у колокольчика → дайджест → переход к привязке → пословный
   дифф → «Актуализировать» (церемония с галочкой). Упомянуть: ночью это
   происходит само.
4. **Утрачено** (1.5 мин): показать привязку, чей текст удалён: статус
   терминальный, тесты сохранены — решение за человеком.
5. **Экран «Тесты»** (2 мин): сводка проектов → реверс-индекс → поиск по
   названию → фильтр «с требующими проверки» → переход к привязке диплинком.
6. **Колокольчик крупным планом** (1 мин): дайджест, строка тишины,
   «не выполняется» + самолечение — «инструмент честен о своей работе».
7. **Финал** (0.5 мин): changelog-модалка — 30+ версий за N недель, темп
   развития; приглашение попробовать (инструкция встроена).

### 2.3. Реплики-мостики (заготовки)
- «Всё, что вы видели руками по кнопке, — ночью происходит само».
- «ReqTrace никогда не меняет статус втихую: либо прогон по правилам, либо
  человек».
- «В Jira мы ходим только читать — создать/сломать там ничего нельзя».
