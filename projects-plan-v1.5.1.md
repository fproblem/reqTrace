# План имплементации: мультипроектность и личные креды (релиз v1.5.1)

План для реализации в ветке `release/v1.5.1`. Цель — превратить единые
глобальные настройки Confluence/Jira в **проекты** с **личными кредами**
каждого участника и скоупингом дерева страниц по доступу.

Решения пользователя (зафиксированы 2026-07-03):
- **Общий проект**: страницы, снимки и привязки — общие для участников
  проекта; каждый участник ходит в Confluence своими кредами.
- **Бывает общий сервер**: разные проекты могут жить на одном
  Confluence-сервере (разные спейсы) → проект ≠ сервер, при добавлении
  страницы возможен явный выбор проекта.
- **Протухшие креды** → проект остаётся в дереве с плашкой «нет доступа»
  (замок + подсказка обновить креды), содержимое закрыто.

## Текущее состояние (что не так)

- Креды Confluence — одна глобальная связка в таблице `settings` (key/value),
  общая на всё приложение; пароль хранится открытым текстом.
- `get_confluence_params(db)` (routers/settings.py) отдаёт эту связку всем
  шести потребителям: `add_page`, `promote_page`, `refresh_page`, `sync_tree`,
  `get_attachment`, `confluence-proxy`.
- Все страницы видны всем пользователям; `Page.confluence_page_id` уникален
  глобально; дерево группируется только по спейсам.
- `jira_base_url` — тоже глобальный.

## Целевое поведение

1. Пользователь в «Настройках» видит **свои проекты**: карточки со статусом
   подключения (подключено / нет доступа / не проверено), может создать
   проект, присоединиться к существующему, обновить/проверить креды,
   отключиться.
2. Дерево страниц: верхний уровень — **проекты пользователя**, внутри —
   спейсы → страницы (как сейчас). Чужие проекты не видны вовсе. Проект с
   невалидными кредами — свёрнут, с замком; клик ведёт в настройки.
3. Все походы в Confluence (добавление/обновление страниц, синк дерева,
   картинки, прокси) выполняются **кредами текущего пользователя** для
   проекта конкретной страницы. Ответ Confluence 401/403 → подключение
   помечается `invalid`, пользователю — понятное сообщение.
4. Контент страниц (снимки в БД тоже!) отдаётся только участникам проекта
   с подключением в статусе `ok` — членство подтверждается работающими
   кредами, это и есть разграничение доступа.
5. Пароли кред шифруются в БД (Fernet, ключ в `.env`).

## Модель данных

```
projects
  id UUID PK
  name VARCHAR(255)                 -- «Банк X»; уникальность по lower(name)
  confluence_base_url TEXT          -- нормализованный: https, lower-host, без завершающего /
  jira_base_url TEXT NULL           -- свойство проекта, не пользователя
  is_demo BOOLEAN DEFAULT false     -- личный демо-проект (см. ниже)
  created_by FK users.id
  created_at

project_credentials                  -- членство = запись здесь
  id UUID PK
  project_id FK projects.id (CASCADE)
  user_id FK users.id (CASCADE)
  confluence_username VARCHAR(255)
  confluence_password_enc TEXT       -- Fernet(CREDENTIALS_KEY)
  status VARCHAR(16)                 -- ok | invalid | unchecked
  last_check_at TIMESTAMPTZ NULL
  created_at, updated_at
  UNIQUE (project_id, user_id)

pages
  + project_id FK projects.id NOT NULL (после миграции) + INDEX
  - UNIQUE(confluence_page_id)  →  UNIQUE(project_id, confluence_page_id)
```

Спейсы проекта отдельно не ведём: они определяются страницами, которые в
проект добавили. Одна и та же Confluence-страница в двух проектах — две
независимые записи `pages` (допустимо, редкий случай).

**Демо-страницы** (`POST /api/pages/demo` — работа без Confluence): при
первом использовании автоматически создаётся личный проект «Демо — <имя>»
(`is_demo=true`, без кред и без записи в project_credentials, участник —
только создатель). Confluence-операции (refresh/promote/sync, вложения)
для демо-проекта отвечают 400 «Демо-страница не связана с Confluence».

**Статус подключения — последнее известное состояние.** Он обновляется
явной кнопкой «Проверить», при сохранении кред и при любом реальном походе
в Confluence (401/403 → invalid). Просмотр уже сохранённых снимков в
Confluence не ходит, поэтому замок может появиться с запозданием — до
первой неудачной операции. Осознанный компромисс: фоновой периодической
ре-валидации в релизе нет.

**Приватность списка проектов**: `GET /api/projects` отдаёт имена и URL
всех проектов любому авторизованному сотруднику — это нужно для
«присоединиться» и приемлемо для внутреннего инструмента (сами данные
проекта закрыты кредами).

## Этап 0 — пререквизиты

- Зависимость `cryptography` (Fernet). `config.py` + `.env(.example)`:
  `CREDENTIALS_KEY` (генерация: `python -c "from cryptography.fernet import
  Fernet; print(Fernet.generate_key().decode())"`).
- Модуль `app/crypto.py`: `encrypt_secret/decrypt_secret` + тесты.

## Этап 1 — модели и миграция 007

- Модели `Project`, `ProjectCredential`; `Page.project_id`.
- Миграция 007 (данные переносим, не теряем):
  1) создать таблицы;
  2) если есть страницы — создать проект «Основной» с
     `confluence_base_url`/`jira_base_url` из старой таблицы `settings`
     (created_by — самый ранний пользователь), привязать ВСЕ страницы к нему;
  3) сменить уникальность `confluence_page_id` на составную; индекс на
     `pages.project_id`;
  4) дроп таблицы `settings` (глобальных кред больше нет — участники вводят

- Downgrade обязателен (точка отката релиза): вернуть уникальность,
  воссоздать `settings` и восстановить в неё `confluence_base_url` /
  `jira_base_url` из проекта «Основной»; пароль невосстановим — после
  отката его нужно ввести заново (зафиксировать в сообщении тега).

## Этап 2 — бэкенд: роутер projects и скоупинг

- Новый `routers/projects.py`:
  - `GET /api/projects` — все проекты (для «присоединиться»): id, имя, URL,
    `joined`, `my_status`.
  - `POST /api/projects` — создать проект + своё подключение одним
    запросом; конфликт имени (по lower) → 409 «Проект с таким именем уже
    есть — возможно, стоит присоединиться к нему».
  - `PUT /api/projects/{id}` — имя/jira_base_url (только участнику).
  - `PUT /api/projects/{id}/credentials` — апсерт своих кред.
  - `POST /api/projects/{id}/credentials/check` — живая проверка
    (лёгкий запрос к Confluence REST, например `/rest/api/space?limit=1`),
    обновляет status/last_check_at.
  - `DELETE /api/projects/{id}/credentials` — отключиться (привязки и
    авторство не трогаем).
  - Создание/апсерт кред требуют успешной проверки подключения — это и есть
    контроль доступа: без работающих кред к Confluence проекта членства нет.
- `app/project_access.py`: зависимость `get_project_creds(project_id, user)`
  → расшифрованные креды со status ok, иначе 403 «Нет доступа к проекту.
  Проверьте креды в настройках». Хелпер `mark_invalid_on_401(...)` — обёртка
  вокруг вызовов Confluence.
- `routers/settings.py` и таблица settings упраздняются;
  `get_confluence_params(db)` → `get_confluence_params(db, project, user)`;
  обновить все 6 потребителей кред, включая `get_attachment` /
  `confluence-proxy` (креды текущего пользователя — cookie с `<img>` уходит
  same-origin, уже работает так с v1.5.0). ⚠ `confluence-proxy` принимает
  относительный URL без page_id — ему нужен явный параметр `project_id`
  (фронт знает проект открытой страницы) для выбора сервера и кред.
- `get_jira_base_url(db)` → `project.jira_base_url`. Отдельный, седьмой
  потребитель — `_render_html` в pages.py (рендер Jira-ссылок в контенте;
  вызывается из get_page/add_page/promote/refresh): jira берётся из
  проекта страницы.
- `GET /api/pages/tree` — только проекты пользователя; формат:
  `[{project_id, project_name, no_access, spaces:[...]}]`; при
  `no_access=true` спейсы не отдаются.
- `add_page`: определить проект по base_url ссылки среди проектов
  пользователя (сравнение нормализованных URL: схема/регистр хоста/слэш);
  если кандидатов >1 — обязательный параметр `project_id` (фронт покажет
  выбор); если 0 — понятная ошибка «Подключите проект с этим Confluence в
  настройках».
- Просмотр контента (`GET /pages/{id}`, highlights, diff, вложения) — через
  проверку членства в проекте страницы.

## Этап 3 — фронтенд

**Настройки (главный экран фичи)** — раздел «Мои проекты» вместо форм
Confluence/Jira:

```
Настройки ▸ Мои проекты                        [+ Подключить проект]

┌─────────────────────────────────────────────────────────────┐
│ ● Банк X                                     [Проверить] [⋮] │
│   Confluence: https://confluence.bankx.ru                    │
│   Jira: https://jira.bankx.ru                                │
│   Мой логин: d.pechkin · пароль (установлен)                 │
│   ● Подключено · проверено сегодня в 14:02                   │
├─────────────────────────────────────────────────────────────┤
│ ● Ритейл Y                                   [Проверить] [⋮] │
│   Confluence: https://wiki.retail-y.com                      │
│   ✖ Нет доступа — Confluence отклонил логин/пароль.          │
│     [Обновить креды]                                         │
└─────────────────────────────────────────────────────────────┘
```

- Карточка проекта: имя, URL'ы, мой логин, статус-индикатор в цветах
  статусов покрытия (зелёный ok / красный invalid / серый unchecked),
  время последней проверки. Меню «⋮»: изменить креды, изменить Jira URL,
  отключиться (с подтверждением).
- «+ Подключить проект» — модал с двумя вкладками:
  «Присоединиться» (выпадающий список чужих проектов + логин/пароль) и
  «Создать новый» (имя, Confluence URL, Jira URL, логин/пароль).
  Сохранение = живая проверка кред; при провале ничего не создаётся.
- Пароль всюду write-only: «(установлен)», пустое поле = не менять.

**Дерево**: уровень проектов сверху (имя + индикатор), внутри текущие
спейсы/страницы. `no_access` — серый узел с замком, tooltip и переходом в
настройки. Состояние сворачивания — в localStorage, как сейчас.

**Добавление страницы**: если URL матчится нескольким проектам — селект
проекта в форме; одному — авто; нулю — ошибка с кнопкой «В настройки».

**SettingsPage**: старые формы удалить; `api/client.ts` — методы projects,
убрать getSettings/updateSettings.

## Этап 5 — ручная e2e

Два пользователя (или два браузера): создать проект → второй присоединяется
своими кредами → оба видят общие привязки; ввести неверный пароль → плашка
«нет доступа», контент закрыт; добавление страницы при двух проектах на
одном сервере → селект проекта.

## Порядок и риски

Порядок: 0 → 1 → 2 → 3 → 4 (5 — вручную в конце). Бэкенд (2) ломает
контракт `/api/settings` — фронт (3) обязателен в том же релизе.

| Риск | Решение |
|------|---------|
| Потеря старых страниц при миграции | Проект «Основной» + NOT NULL только после backfill; downgrade-ветка |
| Пароль в БД открытым текстом (сейчас) | Fernet + CREDENTIALS_KEY в .env; старый глобальный пароль не переносим |
| «Присоединился» с чужими рабочими кредами | Вне модели угроз: рабочие креды = доступ в сам Confluence |
| 401 Confluence посреди работы | mark_invalid + 403 с сообщением; дерево покажет замок при следующей загрузке |
| Забыть потребителя кред (их 6) или jira (`_render_html`) | греп по `get_confluence_params`/`get_jira_base_url` + тест скоупинга вложений |
| Двусмысленность проекта при add_page | явный `project_id` при >1 кандидате |
| Демо-страницы без Confluence | личный демо-проект `is_demo`, Confluence-операции → 400 |
| Замок появляется с запозданием | статус = последнее известное состояние; обновляется проверкой и любым походом в Confluence (осознанно) |
