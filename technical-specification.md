# Техническое задание — ReqTrace MVP

## 1. Назначение

ReqTrace — внутренний инструмент команды QA для визуальной трассировки покрытия требований тестами. Инструмент решает задачу отслеживания связи между фрагментами текста требований в Confluence и тест-кейсами в XRay/Jira, а также выявления изменений в требованиях, влияющих на актуальность существующих тестов.

---

## 2. Стек технологий

| Компонент | Технология |
|---|---|
| Frontend | React + TypeScript |
| Backend | Python + FastAPI |
| База данных | PostgreSQL |
| Развёртывание | Docker Compose (3 контейнера: frontend, backend, postgres) |
| Среда | Mac Mini, локальная сеть офиса |

---

## 3. Пользователи

Команда QA, 7–10 человек. Одновременный доступ к инструменту. Все пользователи видят общие данные: выделения и привязки тестов, созданные любым членом команды, доступны всем.

Авторизация на этапе MVP реализуется через простую форму ввода имени (без пароля). Цель — идентификация автора выделений. Полноценная авторизация выходит за рамки MVP.

---

## 4. Интеграции

### 4.1. Confluence Server REST API

Используется для получения содержимого страниц требований. Confluence Server предоставляет API по адресу `{base_url}/rest/api/content/{pageId}`.

Необходимые операции:
- Получение содержимого страницы по ID (с expand=body.storage,version) — возвращает HTML в формате Confluence Storage Format и номер версии.
- Получение списка версий страницы — для определения, была ли страница обновлена с момента последнего снимка.

Аутентификация — Basic Auth (логин + пароль учётной записи QA-инженера). Учётные данные хранятся на сервере в переменных окружения, не передаются на фронтенд.

### 4.2. Jira + XRay REST API

Используется для формирования ссылок на тесты. На этапе MVP прямая интеграция с XRay API не требуется — тестировщик вводит ключ теста вручную в формате `PROJECT-123`. Инструмент формирует URL на тест по шаблону `{jira_base_url}/browse/{test_key}`.

## 6. Модель данных

### users
| Поле | Тип | Описание |
|---|---|---|
| id | UUID | Первичный ключ |
| name | VARCHAR(255) | Отображаемое имя |
| created_at | TIMESTAMP | Дата создания |

### pages
| Поле | Тип | Описание |
|---|---|---|
| id | UUID | Первичный ключ |
| confluence_page_id | VARCHAR(64) | ID страницы в Confluence |
| confluence_url | TEXT | Полный URL страницы |
| title | VARCHAR(512) | Заголовок страницы |
| space_key | VARCHAR(64) | Ключ пространства Confluence |
| added_by | UUID (FK → users) | Кто добавил страницу |
| created_at | TIMESTAMP | Дата добавления |

### page_snapshots
Снимок содержимого страницы на момент загрузки.

| Поле | Тип | Описание |
|---|---|---|
| id | UUID | Первичный ключ |
| page_id | UUID (FK → pages) | Ссылка на страницу |
| confluence_version | INTEGER | Номер версии в Confluence |
| content_html | TEXT | HTML-содержимое (Confluence Storage Format) |
| fetched_at | TIMESTAMP | Дата загрузки |

### baselines
Фиксация версии, относительно которой оценивается покрытие. Когда тестировщик завершает работу с текущей версией требований (все тесты написаны/актуализированы), он закрепляет снимок как baseline. Последующие сравнения выполняются относительно этого baseline.

| Поле | Тип | Описание |
|---|---|---|
| id | UUID | Первичный ключ |
| page_id | UUID (FK → pages) | Ссылка на страницу |
| snapshot_id | UUID (FK → page_snapshots) | Закреплённый снимок |
| confirmed_by | UUID (FK → users) | Кто закрепил |
| confirmed_at | TIMESTAMP | Дата закрепления |

### highlights
Выделенный фрагмент текста на странице.

| Поле | Тип | Описание |
|---|---|---|
| id | UUID | Первичный ключ |
| page_id | UUID (FK → pages) | Ссылка на страницу |
| snapshot_id | UUID (FK → page_snapshots) | Снимок, на котором создано выделение |
| start_xpath | TEXT | XPath начального текстового узла |
| start_offset | INTEGER | Символьное смещение в начальном узле |
| end_xpath | TEXT | XPath конечного текстового узла |
| end_offset | INTEGER | Символьное смещение в конечном узле |
| text_content | TEXT | Текст выделенного фрагмента (для поиска при изменении структуры) |
| text_before | VARCHAR(100) | Контекст: до 100 символов до выделения |
| text_after | VARCHAR(100) | Контекст: до 100 символов после выделения |
| status | VARCHAR(20) | Статус: `active`, `outdated`, `lost` |
| created_by | UUID (FK → users) | Автор выделения |
| created_at | TIMESTAMP | Дата создания |

Поля `text_content`, `text_before`, `text_after` используются для восстановления позиции выделения при изменении структуры HTML. Если после обновления страницы XPath больше не указывает на ожидаемый текст, инструмент ищет фрагмент по текстовому содержимому и контексту.

### highlight_tests
Связь между выделенным фрагментом и тест-кейсом.

| Поле | Тип | Описание |
|---|---|---|
| id | UUID | Первичный ключ |
| highlight_id | UUID (FK → highlights) | Ссылка на выделение |
| test_key | VARCHAR(64) | Ключ теста в Jira (формат `PROJECT-123`) |
| created_by | UUID (FK → users) | Кто привязал |
| created_at | TIMESTAMP | Дата привязки |

## 7. API Backend

### 7.1. Пользователи

**POST /api/users** — создание/вход пользователя по имени.

**GET /api/users** — список всех пользователей.

### 7.2. Страницы

**POST /api/pages** — добавление страницы Confluence. Принимает URL страницы Confluence, извлекает `pageId` из URL, загружает содержимое через Confluence API, создаёт запись в `pages` и первый снимок в `page_snapshots`, автоматически устанавливает его как baseline.

**GET /api/pages** — список всех отслеживаемых страниц с краткой информацией: заголовок, дата последнего снимка, процент покрытия (доля выделенного текста от общего объёма), наличие обновлений в Confluence.

**GET /api/pages/{page_id}** — детальная информация о странице: текущий снимок, baseline, все выделения с привязанными тестами.

**POST /api/pages/{page_id}/refresh** — загрузка актуальной версии страницы из Confluence. Создаёт новый снимок. Если содержимое не изменилось — новый снимок не создаётся. Если изменилось — запускается процесс проекции выделений (раздел 9).

**POST /api/pages/{page_id}/baseline** — закрепление текущего снимка как нового baseline. Все выделения со статусом `outdated` на этой странице переводятся в `active`.

### 7.3. Выделения

**POST /api/pages/{page_id}/highlights** — создание выделения. Принимает: позицию (XPath + offset), текст фрагмента, контекст. Возвращает созданное выделение.

**DELETE /api/highlights/{highlight_id}** — удаление выделения.

**GET /api/pages/{page_id}/highlights** — все выделения для страницы с привязанными тестами и статусами.

### 7.4. Привязка тестов

**POST /api/highlights/{highlight_id}/tests** — привязка теста к выделению. Принимает `test_key`.

**DELETE /api/highlight-tests/{link_id}** — отвязка теста от выделения.

### 7.5. Сравнение версий

**GET /api/pages/{page_id}/diff** — получение diff между baseline и последним снимком. Возвращает HTML с разметкой изменений (добавленные, удалённые, изменённые блоки).

## 8. Frontend — экраны и компоненты

Дизайн выполняется в соответствии с дизайн-системой Surf: светлый фон (#FFFFFF), градиентные блобы, glassmorphism-карточки, акцентный цвет #7AE05A, системный шрифт, скругления 14–24px.

### 8.1. Экран входа

Простая форма с полем ввода имени и кнопкой входа. Стилистически аналогична экранам входа из дизайн-файлов (Surf-брендинг, карточка на фоне блобов).

### 8.2. Главная — список страниц

Сайдбар (навигация) + основная область контента — по аналогии с admin-panel из дизайн-файлов.

Содержимое основной области:
- Кнопка «Добавить страницу» (ввод URL Confluence).
- Список отслеживаемых страниц в виде карточек. Каждая карточка содержит: заголовок страницы, дата последнего обновления, индикатор покрытия (процент выделенного текста от общего), индикатор наличия изменений в Confluence (если актуальная версия в Confluence новее последнего снимка).

### 8.3. Экран страницы — основной рабочий экран

Центральный экран инструмента. Состоит из двух зон.

**Зона контента** (основная, занимает большую часть экрана). Отображает HTML-содержимое страницы Confluence в том виде, в котором оно существует в Confluence: таблицы, картинки, форматирование, стили. Содержимое рендерится из Confluence Storage Format.

Поверх контента отображаются выделения — подсвеченные фрагменты текста. Цветовая схема выделений:
- **Зелёный фон** (`rgba(122,224,90,0.15)`) — фрагмент покрыт тестами, тесты актуальны (фрагмент не менялся с момента baseline).
- **Жёлтый/оранжевый фон** (`rgba(255,180,0,0.15)`) — фрагмент покрыт тестами, но текст изменился после baseline. Тесты требуют проверки.
- **Красный фон** (`rgba(239,68,68,0.1)`) — фрагмент существовал в baseline, но был удалён или существенно изменён. Привязанные тесты могут быть неактуальны.
- **Текст без выделения** — не покрыт тестами.

При клике на выделенный фрагмент открывается боковая панель с информацией о привязанных тестах.

Пользователь может выделить произвольный фрагмент текста (посимвольно, как в текстовом редакторе) и нажать кнопку «Привязать тесты» — откроется форма ввода ключа теста.

**Боковая панель** (справа, появляется при клике на выделение). Содержит:
- Текст выделенного фрагмента.
- Статус выделения (актуально / требует проверки / утрачено).
- Список привязанных тестов. Каждый тест отображается как кликабельная ссылка в формате `PROJECT-123`, ведущая на страницу теста в Jira.
- Кнопка добавления теста (поле ввода ключа теста).
- Кнопка удаления привязки теста.
- Информация: кто создал выделение, когда.

### 8.4. Панель diff

Доступна на экране страницы через переключатель режимов: «Покрытие» / «Изменения».

В режиме «Изменения» отображается diff между baseline и актуальным снимком:
- Добавленный текст подсвечен зелёным фоном.
- Удалённый текст показан перечёркнутым с красным фоном.
- Неизменённый текст отображается без подсветки.

Этот режим позволяет быстро понять, что именно изменилось в требованиях и где нужно актуализировать тесты.

### 8.5. Верхняя панель страницы

Содержит:
- Заголовок страницы.
- Кнопка «Обновить из Confluence» — загружает актуальную версию.
- Кнопка «Закрепить как baseline» — фиксирует текущий снимок как базовый.
- Индикатор: номер текущей версии, дата baseline, дата последнего снимка.
- Переключатель режимов: «Покрытие» / «Изменения».
- Индикатор общего покрытия страницы (процент).

## 9. Механизм проекции выделений при обновлении страницы

При загрузке новой версии страницы (POST /api/pages/{page_id}/refresh) необходимо определить, какие выделения из baseline сохранили актуальность, а какие требуют внимания.

Алгоритм:

1. Для каждого выделения из baseline берётся его `text_content`, `text_before`, `text_after`, а также XPath-позиция.
2. В новой версии страницы выполняется поиск:
   - Сначала по XPath + offset. Если текст в указанной позиции совпадает с `text_content` — выделение переносится без изменений, статус остаётся `active`.
   - Если текст по XPath не совпадает — выполняется поиск `text_content` в окрестности (контекст `text_before` + `text_content` + `text_after`). Если найдено точное совпадение — позиция обновляется, статус остаётся `active`.
   - Если найдено частичное совпадение (текст изменён, но контекст узнаваем) — позиция обновляется, статус переводится в `outdated`.
   - Если текст не найден — статус переводится в `lost`.

Выделения со статусом `lost` отображаются в отдельном блоке боковой панели как «утраченные привязки» с указанием исходного текста и привязанных тестов.

## 10. Развёртывание

### docker-compose.yml

Три сервиса:
- **postgres** — PostgreSQL 16, volume для данных, порт 5432.
- **backend** — Python-приложение FastAPI, порт 8000. Зависит от postgres. Переменные окружения: `DATABASE_URL`, `CONFLUENCE_BASE_URL`, `CONFLUENCE_USERNAME`, `CONFLUENCE_PASSWORD`, `JIRA_BASE_URL`.
- **frontend** — React-приложение (nginx для раздачи статики), порт 3000. Зависит от backend. Проксирует `/api/*` на backend.

Запуск: `docker-compose up -d`.

### Переменные окружения

| Переменная | Описание |
|---|---|
| DATABASE_URL | Строка подключения к PostgreSQL |
| CONFLUENCE_BASE_URL | Базовый URL Confluence Server |
| CONFLUENCE_USERNAME | Логин для Confluence API |
| CONFLUENCE_PASSWORD | Пароль для Confluence API |
| JIRA_BASE_URL | Базовый URL Jira (для формирования ссылок) |

## 11. Ограничения MVP

- Авторизация упрощённая (по имени, без пароля). Достаточно для идентификации автора действий внутри команды.
- Тесты привязываются вручную по ключу (без поиска по XRay API).
- Одна baseline на страницу в каждый момент времени. История baseline не хранится.
- Инструмент не отправляет уведомления об изменениях — тестировщик сам инициирует обновление.
- Diff формируется на стороне сервера. Сложные структурные изменения HTML (перенос блоков, слияние таблиц) могут отображаться некорректно.
